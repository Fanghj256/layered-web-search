# 分层联网调研

用于 AGENTS.md「查证分档」里判为**完整流程**的情形。若只是单点事实、且有权威单一来源（官网、官方公告）可定，一次检索并核对来源即可收工，不必走完下面全部步骤。

## 流程

0. **先判问题类型**：评价类（值不值得用／买／上）与探索类（找人、找灵感、找对标）先提醒我人工搜索，不要只凭搜索结果下结论。
1. **确认时间范围**：先用 `date` 确认当前日期；请求模糊时先问我一句。
2. **粗搜**：`web_search_exa` 发 1–2 个宽查询。query 用自然语言描述"我想要的页面"，不要堆关键词。
3. **读全文**：对高相关链接用 `web_fetch_exa` 抓正文。数字、公告号、日期、引文必须来自正文，不能只看搜索摘要。
4. **缺口驱动的第二轮**：读完判断还缺什么，用 `web_search_advanced_exa` 细化——加机构实体名、用 `startPublishedDate`／`endPublishedDate` 限定时间、用 `includeDomains` 锁定权威来源（如 gov.cn、机构官网）。
5. **工具降级**：`web_fetch_exa` 抓不到（动态渲染、反爬、登录墙）时按来源性质分两路。已知站点、需要登录态的用 `ego-browser`（与本机登录态共用，脚本走 `ego-browser nodejs`，正文用 `page.evaluate()` 取 `document.body.innerText`）；来源可疑、需要隔离环境的用 `playwright-cli`（默认 headless、profile 只在内存，关掉即清）。两路都拿不到就标注"未能核实"，不要硬凑。代码类问题用 `gh` CLI（`gh search code`、clone 后 grep），不要用搜索引擎硬搜代码。
6. **交叉验证**：关键事实至少 2 个独立来源；来源冲突时标注分歧，不自行调和。
7. **输出**：分类归纳，能用表格用表格；每条结论附来源链接，并标注「已证实／未证实／时效未知」。

## 守住这三条

- **出处**：引文与文献（谁提出的、哪年、什么期刊、数据出自哪份报告）一律核实原文；宁可写"未能核实"，也不给一个看起来对的引用。
- **高风险**：健康、法律、金融、安全这类问题优先权威来源、注明不确定性，并说明不构成专业意见。
- **可核对**：结论要能落成一句可核对的话——来源 + 时间 + 结论，而不是"网上说"。
