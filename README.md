# 分层联网搜索策略

> 给 AI Agent 的一套联网调研方法：**会分档、会降级、知道什么该交给人工。**

**中文** | [English](README.en.md)

本仓库包含两个可直接安装的文件（规则 + 技能）和一份完整配置教程，让 Agent 在联网查资料时按固定纪律工作，而不是"搜一次就编"。

适用于 ZCode（本仓库在 ZCode 3.x 上验证）、Claude Code、Cursor 等支持 `AGENTS.md` / `CLAUDE.md` 与 Skill 的客户端。

---

## 它解决什么问题

不装这套东西时，Agent 联网常见的翻车方式：

- **搜一次就下结论**：把搜索摘要当事实，数字、日期、公告号全凭印象
- **该查的不查**：凭记忆编造"看起来对"的引用和数据
- **轻活重做 / 重活轻做**：一个单点事实也跑五轮检索；真正要写进材料的问题反而只搜一次
- **评价类也一本正经下结论**：AI 没法替你判断"值不值得用"，却给出斩钉截铁的答案

这套策略用**判断规则 + 分档流程 + 人机分工**解决以上四点。

## 核心设计

### 1. 四层降级链（按获取成本排序）

| 层 | 工具 | 拿到什么 | 什么时候升级到下一层 |
|---|---|---|---|
| ① 粗搜 | Exa `web_search_exa` | 线索 + 摘要 | 摘要不足以回答 |
| ② 抓全文 | Exa `web_fetch_exa` | 正文（数字、文号、日期） | 抓不到（动态渲染 / 反爬 / 登录墙） |
| ③ 浏览器兜底 | Playwright / Chrome | 交互后的页面内容 | —— |
| ④ 站点专用通道 | `gh` CLI / `curl` / 专用 API | 代码、结构化数据 | —— |

**核心原则：能用轻的就不用重的。** 不是每个任务都跑满四级——单点事实在第①层就该收工。

### 2. 查证分档

- **轻核实**：单点事实、权威单一来源可定 → 一次检索并核对来源，收工
- **完整流程**：要写进对外材料 / 要下判断 / 涉及名额·截止·费用 / 多来源冲突 / 要引用文献 → 走 `web-research` 技能的完整链路

### 3. 人机分工（最容易被忽略）

| 需求类型 | 交给谁 | 为什么 |
|---|---|---|
| 确定性、可验证（如"某公告的文号"） | AI 搜 | 有明确答案，检索汇总效率高 |
| 评价类（"值不值得用"） | 人：翻 issue、看 commit | 大模型容易被"假大空"的话牵着走 |
| 探索类（找人、找灵感、找对标） | 人：泡论坛精华帖、翻用户主页 | 这类需求依赖"人的历史轨迹"，AI 搜索还做不好 |

### 4. 输出纪律

- 每条结论附来源链接
- 标注「已证实 / 未证实 / 时效未知」
- 来源冲突时标注分歧，不自行调和
- 当次用户的显式格式要求优先于默认呈现偏好（冲突裁决）

## 工作流

```text
用户提问
  │
  ├─ ① 判断（AGENTS.md：五问 + 七类落点）
  │     ├─ 不需要联网 → 直接回答
  │     ├─ 评价 / 探索类 → 提醒人工搜索
  │     └─ 事实类 → 继续
  │
  ├─ ② 分档
  │     ├─ 轻核实 → 一次检索，核对来源，收工
  │     └─ 完整流程 → 加载 web-research 技能
  │
  └─ ③ 完整流程（web-research）
        date / 时间范围 → 粗搜 → 抓全文 → 缺口驱动第二轮
        → （抓不到）浏览器兜底 → 交叉验证 → 带来源 + 标注输出
```

## 快速开始

1. **拿一个 Exa API key**（免费额度够用）  
   打开 <https://dashboard.exa.ai> → API Keys → Create Key。  
   新账号送 $20（约 2800 次搜索），免费档每月再送 $10。  
   *不想注册：Exa MCP 支持匿名模式（有限流），跳过 key 即可。*

2. **装两个文件**

   ```bash
   # 规则（用户级，所有工作区生效）
   cp AGENTS.md ~/.zcode/AGENTS.md

   # 技能
   mkdir -p ~/.zcode/skills/web-research
   cp skills/web-research/SKILL.md ~/.zcode/skills/web-research/
   ```

3. **配置 Exa MCP**（ZCode 示例）

   编辑 `~/.zcode/cli/config.json`，在 `mcp.servers` 下加入：

   ```json
   "exa": {
     "type": "http",
     "url": "https://mcp.exa.ai/mcp?tools=web_search_exa,web_fetch_exa,web_search_advanced_exa",
     "timeoutMs": 60000,
     "headers": { "x-api-key": "YOUR_EXA_API_KEY" }
   }
   ```

4. **新开一个会话**，看到 `web_search_exa` / `web_fetch_exa` / `web_search_advanced_exa` 即成功。

详细步骤（含三个必踩的坑、验证清单、排错表、卸载清单）见 **[配置教程](docs/配置教程.md)**。

## 设计取舍：为什么默认用"软触发"

这套策略有两种触发方式，本仓库默认采用第一种：

| | 软触发（默认） | 硬触发（可选） |
|---|---|---|
| 机制 | `AGENTS.md` 规则 + 模型自行加载技能 | hook 关键词注入 / `/research` 命令 |
| 优势 | 自带"轻 / 重分档"，能按任务伸缩；零额外配置；跨客户端可移植 | 触发确定，不依赖模型判断 |
| 劣势 | 依赖模型遵从（长会话可能漂移） | 无分档：轻检索也按全流程执行 |

**对照实验**（同一模型、同一任务，各 4 次）：两种方式在触发率、流程完整度、输出质量上全部打平；成本上软触发更低——在"复合任务 + 嵌入式检索"场景里，对比无策略基线，软触发 +24% token、硬触发 +43%（硬注入把一次单词查询也当成完整调研来跑）。实验为小样本、单模型，结论是方向性的。

因此：**默认软触发；只在需要"任何含触发词的消息都必须走全流程"时，才启用 `examples/` 里的 hook 或命令。**

## 适配其他客户端

规则文件与技能是跨客户端通用的，MCP 配置按客户端格式改写：

| 客户端 | 配置文件 | 写法 |
|---|---|---|
| **ZCode** | `~/.zcode/cli/config.json` | 嵌套 `mcp.servers`，`"type": "http"` + `url` |
| **Claude Code** | 项目 `.mcp.json` | 顶层 `mcpServers`，`"type": "http"` + `url`；或 `claude plugin install exa@claude-plugins-official` |
| **Cursor** | `~/.cursor/mcp.json` | `mcpServers` + `url` |
| **VS Code** | `.vscode/mcp.json` | 官方一键安装，或手写 `url` |
| 不支持远程 MCP 的客户端 | —— | `npx -y mcp-remote https://mcp.exa.ai/mcp` |

规则文件：ZCode 用 `AGENTS.md`，Claude Code 用 `CLAUDE.md`（内容相同，改个名即可）。

## 常见问题

- **工具不出现？** 新开会话（MCP 和技能都在会话启动时加载）；ZCode 可到「设置 → MCP」看连接状态。
- **中国网络连不上？** `mcp.exa.ai` 直连不稳定，需要代理；终端里记得设 `HTTPS_PROXY`。
- **想换搜索供应商？** Tavily / Firecrawl / Brave 都有 MCP，把第①层换掉即可，规则和技能不用动（把技能里的工具名替换成对应的）。
- **`date` 显示的日期不对？** 容器 / 沙箱的时钟可能偏差，以会话系统注入的当前日期为准。
